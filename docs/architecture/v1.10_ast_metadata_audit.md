# v1.10 Phase 1: AST Metadata Audit

This document captures the read-only audit of the current compiler architecture (Lexer → AST → Generator → IR) to establish what semantic information is available, what is discarded, and what must be added for v1.10 intelligence tooling.

## 1. Metadata Preservation Matrix

| Metadata | AST currently has? | Preserved in IR? | Location lost? |
| --- | --- | --- | --- |
| Components | Yes | No (flattened) | Yes (discarded) |
| Component hierarchy | Yes | No (flattened) | Yes (discarded) |
| Attributes | Yes | Yes (OpSetAttribute) | Yes (token pos lost) |
| Variables/state | Yes | Yes (OpDeclareState) | Yes (token pos lost) |
| Event handlers | Yes | Yes (OpAddEvent) | Yes (token pos lost) |
| Expressions | Yes (FStrings) | Yes (OpBindText) | Yes (token pos lost) |
| Imports | No | No | Yes (doesn't exist) |
| Cross-file references | No | No | Yes (doesn't exist) |
| Source file | No | No | Yes (doesn't exist) |
| Line/column | No (Lexer only) | No | Yes (dropped in Parser) |
| Symbol identity | No | No | Yes (doesn't exist) |
| Parent/child relationship | Yes (AST tree) | Yes (ID references) | N/A |
| Type information | No (weakly inferred) | No | Yes (doesn't exist) |

## 2. Information Flow Analysis

```text
Source (.tin)
  ↓
Lexer       ← (CAPTURES Line/Col)
  ↓
Parser      ← (DISCARDS Line/Col; captures raw Component/State/Node structure)
  ↓
AST         ← (Lacks file URIs, Symbol IDs, Line/Col)
  ↓
Generator   ← (DISCARDS Component boundaries; inlines everything into a flat array)
  ↓
IR          ← (Retains structural mutations and parent/child layout only)
```

## 3. Critical Questions

### What can v1.10 reuse immediately?
- **Lexer Location Data**: The lexer natively tracks `Line` and `Col` for every `Token`.
- **AST Topologies**: The structural parsing of `Component`, `DefNode` (mutations), and `StateDecl` is robust. 

### What metadata is currently being discarded?
- **Source mappings**: The parser explicitly uses `p.curToken.Line` for errors but never attaches it to the resulting AST nodes.
- **Component boundaries**: The generator flattens all components into a single 1D matrix of WebAssembly DOM operations, entirely erasing semantic boundaries between components.

### What metadata must be added to the AST?
- **Location Context**: `Line`, `Col`, `Length`, and `SourceURI` must be added to the `ASTNode` interface.
- **Imports/Exports**: The AST must track module dependencies explicitly rather than relying on global resolution.
- **Symbol Identifiers**: Variables, components, and functions need stable identities to track references across files.

### What metadata belongs in Typed Semantic IR rather than syntax AST?
- **Cross-File Resolution Graphs**: The linking of `<Card>` to `Card.tin` belongs in a semantic graph, not the file-local AST.
- **Type Bounds**: Component props, state types, and mutation signatures.
- **Semantic Tokens**: Data that categorizes symbols (e.g. `type: "variable", modifier: "readonly"`) for the LSP.

## 4. Final Classification

```text
REUSE                 : Lexer location tokens, AST node structures, Generator IR schema
EXTEND AST            : Add SourceURI, Line, Col, and import/export declarations
ADD TO SEMANTIC IR    : Typed props, component boundaries, symbol bounds
DERIVE IN GRAPH       : Cross-file references, workspace dependencies, hover definitions
INTENTIONALLY DISCARD : N/A (We need all current information)
```
