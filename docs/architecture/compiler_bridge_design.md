# Phase N Compiler Bridge Design

## Executive Summary
This document outlines the design architecture for deprecating the Python regex parser in favor of delegating all compilation strictly to the Go AST parser, cementing Go as the canonical `.tin` compiler.

In this design, Python steps back to act as an integration API and CLI facade, invoking the Go binary as a subprocess. Additionally, the generation of `app.ir.bin` is shifted exclusively to the Go pipeline.

## System Architecture

```text
.tin Source
    ↓
Go Lexer/Parser (tinui.exe)
    ↓
Go AST Representation
    ↓
Canonical IR Generation
    ↓
app.ir.json
    ↓
Canonical Binary Encoder (To be implemented in Go)
    ↓
app.ir.bin
    ↓
TinPyUI Runtime (WASM / Python App)
```

## Python Subprocess Wrapper Interface

### 1. Go Compiler CLI Contract
To delegate compilation, the Python bridge (`aot_compiler.py`) will shell out to the Go CLI using the following contract:

- **Command:** `tinui build <file.tin>` or `tinui check <file.tin>`
- **Output Paths:** The Go binary natively handles resolving dependencies (e.g., scanning `scenes/*.tin`) and outputs strictly to `dist/app.ir.json` and `dist/index.html`.
- **Exit Codes:** 
  - `0`: Success.
  - `1`: Syntax/Parse errors encountered.
- **Stdout/Stderr:** The Go CLI prints ANSI-colored syntax diagnostics to stdout. The Python bridge should capture this and stream it to the user.

### 2. PyPI Distribution Implications (Unresolved Challenges)
**Locating the Executable:** Python packages installed via PyPI (`pip install tinpyui`) do not automatically compile Go source code.
- **Problem:** If a user runs `tinpyui build`, the Python CLI must find the `tinui` executable.
- **Solution Strategy:** The PyPI deployment pipeline must be modified to build and bundle the compiled Go binaries (`tinui-windows-amd64.exe`, `tinui-linux-amd64`, `tinui-darwin-arm64`) directly into the Python wheel, similar to how tools like `ruff` package Rust binaries. 
- **Alternative:** Require developers to install the `tinui` Go binary globally via Homebrew/Go install, and use `shutil.which('tinui')` in Python.

## Canonical Binary IR Generation (Go)
Currently, `app.ir.bin` is exclusively generated by Python (`binary_ir.py`).
Following the new design, the Go compiler must assume authority over this optimized format.
- **Design Action:** A new `binary_encoder.go` module must be implemented in `src/compiler/` that mirrors the exact struct-packing logic of Python's `encode_binary_ir`.
- **Pipeline:** Upon successful generation of `app.ir.json`, `main.go` will automatically compress it to `app.ir.bin`.

### Backward Compatibility for Python `encode_binary_ir` Users
Programmatic users who currently `from tinpyui.core.binary_ir import encode_binary_ir` to manually construct matrices in memory will remain perfectly compatible. 
The Python `binary_ir.py` module will NOT be deleted; it will simply be demoted to a utility library for in-memory manipulation rather than being part of the core file-compilation pipeline.

## Actionable Next Steps (Implementation Phase)
1. Write `src/compiler/binary_encoder.go` to match the exact byte-packing format of `binary_ir.py`.
2. Update `main.go` inside `compileFile()` to output `app.ir.bin` to the `dist/` folder.
3. Update Python's `aot_compiler.py` to strip out the regex engine and replace it with a robust `subprocess.run(["tinui", "build", entry_file])` wrapper.
4. Establish the wheel distribution strategy for shipping Go binaries via PyPI.
