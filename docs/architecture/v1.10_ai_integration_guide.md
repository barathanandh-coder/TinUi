# TinPyUI v1.10 — AI Integration Guide

This guide is for developers building external AI agents, Language Server clients, and IDE integrations targeting TinPyUI v1.10. It explains the workflow and architectural boundaries required to interact safely with the TinPyUI backend.

## 1. Architectural Philosophy

The core principle of TinPyUI v1.10's AI integration is:

> **TinPyUI retains ultimate semantic authority. External AI agents consume the Machine Protocol to understand the workspace, but the backend controls execution.**

When your AI agent interacts with TinPyUI, it is subject to the following rules:
- **TinPyUI validates your AST.**
- **TinPyUI enforces strict filesystem version boundaries.**
- **TinPyUI detects and prevents global semantic regressions.**
- **TinPyUI enforces human approval pipelines.**

You do not simply "write a file." You propose a transaction. TinPyUI decides if it commits.

## 2. Agent Workflow Lifecycle

A robust AI agent operates in the following loop over JSON-RPC (stdin/stdout):

### Step 1: Initialization
Start the TinPyUI daemon and initialize the workspace by sending the standard LSP `initialize` method.
Provide file structures using `textDocument/didOpen` and keep them updated with `textDocument/didChange`.
*Note: Your client/IDE acts as the master VFS synchronization driver.*

### Step 2: Discovery
Gain an understanding of the project architecture instantly using `context.architecture` to fetch the global dependency graph.
To understand a specific module, query `context.file`.

### Step 3: Targeted Context Queries
When tasked with a refactor or feature addition, identify relevant nodes and boundaries:
- `context.search` (Find a component)
- `context.symbol` (Read a symbol's AST)
- `context.related` (Find linked states/methods)
- `context.impact` (Predict blast radius of a change)

### Step 4: Propose a Transaction
When your agent computes code modifications, you **must not** bypass the sandbox. Send a `context.propose` request:
```json
{
  "method": "context.propose",
  "params": {
    "operation": "replace",
    "uri": "file:///path/to/Button.tin",
    "expected_version": 12,
    "replacement": "component Button():\n    pass"
  }
}
```
TinPyUI will sand-box the compilation. If syntactically valid, it returns a cryptographically secure `ProposalID`.

### Step 5: Human / Host Approval
Your agent must pause and present the `ProposalID` to the human developer or IDE host system. TinPyUI enforces a strict boundary here; the proposal is dormant until explicitly committed.

### Step 6: Apply the Transaction
Execute the proposal with `context.apply`:
```json
{
  "method": "context.apply",
  "params": {
    "proposal_id": "prop_1234abcd",
    "uri": "file:///path/to/Button.tin",
    "expected_version": 12
  }
}
```

### Step 7: Inspect the Outcome
TinPyUI will perform a deep semantic sync across the *entire workspace*. If your change broke references in *other* files, the transaction is **rolled back atomically**.

**Crucial Distinction**:
- **JSON-RPC Error**: If the JSON-RPC response contains an `"error"` (e.g., `-32003` Stale Version), the request itself failed. You must re-sync `textDocument/didChange` and propose again.
- **Transaction Rejected**: If the response is successful but contains `"Applied": false` (e.g., `"Reason": "Semantic regression detected"`), your request processed correctly, but your code was semantically destructive and rolled back. Analyze the `context.impact` and try again.

## 3. Concurrency and Conflict Handling

Your agent operates concurrently with the human developer typing in the IDE.
- Always provide the `expected_version` incremented by LSP `textDocument/didChange`.
- If the human types *while* your agent is compiling a proposal, the proposal's version will drift. `context.apply` will return a `-32003` JSON-RPC error.
- Do not poll. The Machine Protocol handles overlapping `context.apply` and `textDocument/didChange` locking asynchronously.

## 4. What an Agent Must NOT Do

- ❌ **Do not bypass the VFS**: Writing directly to the filesystem bypasses semantic checking and causes data races.
- ❌ **Do not cache internal structures**: `ArchNode` schemas return stable JSON, but internal IDs or file configurations may change. Always query fresh data.
- ❌ **Do not ignore `Applied: false`**: Re-proposing the exact same source after a semantic rollback will always fail. You must ingest the error, query unresolved references, and fix your code block.

By adhering to the Machine Protocol, external AI agents gain unprecedented, safe, and transactionally isolated control over complex TinPyUI codebases.
