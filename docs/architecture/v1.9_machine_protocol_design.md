# v1.9 Architecture: The Machine-Operable Development Protocol

## The Core Philosophy
TinPyUI v1.9 transitions the framework from being merely "AI-friendly" (via documentation) to **AI-Native** and **Machine-Operable**. 

The fundamental principle: **Do not build an AI-specific API. Build a stable, deterministic machine-to-machine development protocol that any tool—AI coding agents, CI/CD pipelines, IDEs, or automated repair bots—can consume flawlessly.**

## The `tinui agent` Interface

Instead of scraping terminal logs and parsing human-readable text, machines interact with TinPyUI via a structured data pipeline. The protocol commands emit structured JSON to standard output.

### Proposed Command Surface

```text
tinui agent
├── discover       (Scan workspace and locate TinPyUI boundaries)
├── context        (Provide architectural rules and structural context)
├── schema         (Dump AST schemas and component dictionaries)
├── project        (Output project topology and module configurations)
├── create         (Scaffold components/projects deterministically)
├── check          (Run parser and emit structured diagnostics)
├── diagnostics    (Retrieve all cached project errors/warnings)
├── graph          (Emit the component dependency and state graph)
├── build          (Produce app.ir.bin silently and emit build stats)
├── run            (Spin up headless environment or dev server)
├── test           (Run structural or unit tests with JSON reporting)
├── inspect        (Query specific nodes or memory in the ABI)
└── repair         (Accept JSON patches for automated repair)
```

## The Diagnostic Loop
The most critical evolution is moving from human-readable stderr logs to **Structured Diagnostics**. 

### Example Output from `tinui check --json pages/login.tin`
```json
{
  "status": "failed",
  "diagnostics": [
    {
      "error_code": "TIN-0012",
      "category": "syntax",
      "severity": "fatal",
      "file": "pages/login.tin",
      "line": 14,
      "column": 9,
      "message": "Expected component attribute, found ILLEGAL",
      "context_snippet": "Button(text=\"Add\", on_click: increment)",
      "suggestion": "Replace ':' with '=' for attribute assignment.",
      "repairable": true,
      "ast_node": "AttributeDefinition"
    }
  ]
}
```

### The Autonomous Machine Loop
With structured diagnostics, the AI-agent loop becomes deterministic:
1. **Emit Code**: AI generates `.tin` code.
2. **Check**: AI executes `tinui check --json`.
3. **Parse**: AI natively parses the JSON diagnostic array.
4. **Target**: AI uses `file`, `line`, and `column` to pinpoint the failure.
5. **Repair**: AI applies the `suggestion` or reasons over the `error_code`.
6. **Re-check**: Loop continues until `status: "passed"`.

## Integration with v1.8

This vision perfectly builds on the v1.8 baseline:
- The **Go Compiler** naturally supports structured JSON serialization and AST traversal.
- The **Python Bridge** can easily expose these `tinui agent` commands programmatically for Python-based test runners or bots.
- The **Canonical IR** ensures that when the machine inspects or builds, there is only one source of truth.
