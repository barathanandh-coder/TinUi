# TinPyUI v1.10 — Machine Protocol Specification

This document defines the formal Machine Protocol contract for TinPyUI v1.10. It defines the JSON-RPC endpoints, parameters, and structural schemas that an external AI agent or IDE client uses to interact with the TinPyUI backend.

## 1. Terminology & Standards

- **Protocol Format**: Standard JSON-RPC 2.0 via stdin/stdout.
- **URI Format**: Standard LSP file URIs (`file:///...`). Note: References to the framework internally are often termed `tinpy://` conceptually, but all disk operations use standard `file://` URIs.
- **Agent Integration**: The AI agent acts as a client sending `context.*` requests to the TinPyUI background daemon.

## 2. Standard LSP Endpoints Supported

TinPyUI fully consumes standard LSP synchronization methods to maintain its semantic workspace. Agents/IDEs must provide these to keep the VFS up-to-date:

- `initialize`
- `textDocument/didOpen`
- `textDocument/didChange` (Full sync)
- `textDocument/didClose`

*Note: These behave identically to standard Language Server Protocol specifications.*

## 3. The `context.*` API (Read Operations)

These methods provide near-instantaneous semantic queries against the active workspace.

### `context.file`
Retrieves the syntax and structural breakdown of a single file.
- **Params**: `{ "uri": "file://..." }`
- **Result**: JSON representation of the file's semantic graph (imported symbols, exported components, states, etc.).

### `context.symbol`
Retrieves the definition and properties of a specific symbol.
- **Params**: `{ "id": "symbol_name" }`
- **Result**: The symbol's definition node, including its type and defining file URI.

### `context.search`
Fuzzy searches the entire semantic workspace for symbols.
- **Params**: `{ "query": "search_string" }`
- **Result**: Array of matching symbol definitions.

### `context.related`
Finds symbols semantically related to a given component or state.
- **Params**: `{ "id": "symbol_name" }`
- **Result**: Array of related nodes (e.g., event handlers linked to a state).

### `context.impact`
Calculates the blast radius if a symbol is modified.
- **Params**: `{ "id": "symbol_name" }`
- **Result**: Serialized `ArchNode` graph showing dependents, references, and transitive linkages.

### `context.dependencies` / `context.dependents`
Fetches strict unidirectional dependency chains.
- **Params**: `{ "id": "symbol_name" }`
- **Result**: Array of serialized `ArchNode` schemas.

### `context.architecture`
Fetches a high-level representation of the entire workspace graph.
- **Params**: `{}`
- **Result**: Fully serialized `ArchNode` schema representing the global project architecture.

## 4. The `context.*` API (Write / Mutator Pipeline)

This pipeline facilitates AI-driven code modification safely via Proposals.

### `context.propose`
Submits a string-based patch for a specific file version. The backend performs semantic sandboxing and syntactic validation.
- **Params**:
  ```json
  {
    "operation": "replace",
    "uri": "file://...",
    "expected_version": 4,
    "replacement": "component Foo():\n    pass\n"
  }
  ```
- **Result**:
  ```json
  {
    "Valid": true,
    "ProposalID": "prop_a1b2c3",
    "Reason": ""
  }
  ```

### `context.apply`
Commits a validated Proposal to the VFS and verifies global semantic integrity.
- **Params**:
  ```json
  {
    "proposal_id": "prop_a1b2c3",
    "uri": "file://...",
    "expected_version": 4
  }
  ```
- **Result**:
  ```json
  {
    "Applied": true,
    "Reason": "Committed successfully"
  }
  ```
  *Note: If a semantic regression occurs across the workspace, the backend rolls back the change atomically and returns `{"Applied": false, "Reason": "Semantic regression detected"}`.*

## 5. Stable Error Codes

The TinPyUI Machine Protocol utilizes standard JSON-RPC error structures. The following error codes are formally part of the v1.10 compatibility contract:

### Standard JSON-RPC Codes
- **`-32603` (Internal Error)**: The dispatcher encountered a panic or unhandled fault. The daemon remains alive and subsequent requests are safe.
- **`-32602` (Invalid Params)**: Malformed JSON or missing required fields (e.g., missing URI).

### TinPyUI Domain Codes
- **`-32000` (API Not Initialized)**: The `AIContext` or `GlobalWorkspace` is not ready.
- **`-32001` (Resource Error)**: Underlying file I/O error or the requested file/URI was not found in the semantic workspace.
- **`-32002` (Entity Not Found)**: The requested document is not open, the requested symbol does not exist, or the ProposalID is missing/already consumed.
- **`-32003` (Version Mismatch)**: The LSP `version` or `expected_version` supplied by the agent is older than the authoritative VFS version. The agent must synchronize and retry.

## 6. Serialization Schemas

The data returned by structural queries (e.g., `context.architecture`, `context.impact`) uses a stable JSON format. 
*Note: The underlying Go structures (such as `ArchNode`, `SemanticWorkspace`, or `FileAST`) are internal implementation details and may change. Clients must only rely on the external JSON shapes returned over the wire.*
