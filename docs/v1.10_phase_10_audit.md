# TinPyUI v1.10 — Phase 10: Scope and Finalization Audit

The goal of Phase 10 is to transition TinPyUI v1.10 from feature development into a finalized, public-facing product contract. We must strictly define boundaries, APIs, and compatibility contracts before formal release. No new features will be developed in this phase.

## 1. What becomes public API?
- **The Core LSP Endpoints**: `initialize`, `textDocument/didOpen`, `didChange`, `didClose` — these are universal and form the baseline integration for any IDE.
- **AI Context Read Endpoints**: `context.search`, `context.file`, `context.dependents`, `context.references`, `context.impact`. These allow external agents to safely query the semantic model.
- **AI Mutator Pipeline**: `context.propose` and `context.apply`. The transaction boundary is stable enough to be part of the v1.10 public machine protocol.

## 2. What remains internal?
- **The internal VFS/Workspace locking mechanisms** (`docMutex`, `vfsMutex`, `ws.mu`).
- **Semantic indexing internals** (AST representation, specific node structures) should remain opaque implementation details to avoid freezing our ability to optimize the compiler.
- **Proposal Storage**: The active proposals registry (`AIContext.proposals`) is internal. Clients only interact via `ProposalID`.

## 3. Which machine-protocol operations are stable?
The following JSON-RPC envelopes are guaranteed stable for v1.10:
- Standard LSP text synchronization methods.
- The `context.*` endpoints listed in Section 1.
- Error codes (-32603 for internal error, -32002 for missing document, -32003 for stale version, -32004 for semantic regression).

## 4. Which semantic graph structures are stable?
- The external representation emitted by `context.impact` and `context.dependents` (e.g., `ArchNode` interfaces presenting symbols, file URIs, and relationship vectors) is stable.
- The internal `SemanticIndex` and `FileAST` are *not* stable and should not be relied upon directly by extensions or plugins.

## 5. What does an external AI agent actually get access to?
An external agent acting via JSON-RPC gets:
- **Read access:** Near-instantaneous semantic resolution of dependencies, references, symbols, and impact radii across the entire workspace.
- **Write access:** The ability to submit string-based source replacements via `context.propose`, which are sandboxed and semantically validated, yielding a deterministic `ProposalID`.
- **Apply access:** The ability to execute a `ProposalID` via `context.apply`, subject to human approval and VFS version constraints, with atomic rollback guarantees.

## 6. What is the v1.10 compatibility contract?
- **Semantic Compatibility:** The external AI JSON-RPC API is versioned at `1.0`. Any changes to the `context.*` endpoints will be strictly additive until `2.0`.
- **Python Runtime Compatibility:** TinPyUI v1.10 provides 100% backward compatibility with all Python UI scripts written for v1.9. 
- **WASM Packaging:** The AOT build pipeline outputs remain compatible with existing deployment targets (Desktop, Android, iOS, Web).

## 7. What documentation is required?
- **Machine Protocol Specification:** A formalized document describing the `context.*` endpoints, expected inputs/outputs, and error codes.
- **AI Integration Guide:** A tutorial showing how to connect an external AI agent to the TinPyUI backend.
- **Transaction Lifecycle Guide:** Detailed explanation of the Propose → Validate → Apply flow and how versioning/locking works.

## 8. What is deliberately postponed to v1.11?
- **AI Automated Refactoring Engine:** Advanced capabilities where the backend itself orchestrates multi-file refactors.
- **Cross-Language Semantics:** Deep semantic mapping between the Python UI code and generated Native/WASM code (currently focusing purely on `.tin` and Python script boundaries).
- **Interactive Proposal UI:** A built-in GUI for human review of proposals; this remains the responsibility of the connecting IDE client for v1.10.

## 9. What gets frozen before release?
- The JSON-RPC `agent` package API surface.
- The `SemanticWorkspace` data flow invariants.
- The `context.apply` rollback mechanisms.
- All core `compiler` AST structures.
