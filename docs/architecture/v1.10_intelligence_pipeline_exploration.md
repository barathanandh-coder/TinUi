# v1.10 Intelligence Pipeline Exploration

*Status: DRAFT / EXPLORATION PHASE*

The v1.10 lifecycle centers on expanding TinPyUI from a rapid compilation engine into a semantically aware development environment. Based on the selected vectors, v1.10 will investigate a unified "Intelligence Pipeline":

```text
1. Typed Semantic IR 
   (Strict type bounds and guarantees for the IR structure)
        ↓
2. Semantic Intelligence Graph 
   (Queryable cross-file AST, symbol resolution, and component boundaries)
        ↓
3. Advanced LSP 
   (Rename, references, semantic tokens, context-aware code actions)
        ↓
4. AI-Native Workflows 
   (Autonomous agent analysis, self-repair mechanisms, architecture understanding)
```

## Exploration Goals

Before any implementation, we must investigate and define:

### 1. The Semantic IR Contract
How do we type the current dynamic IR? Should we introduce a strict schema for nodes (e.g., `ComponentNode`, `NativeNode`, `ControlNode`) that the runtime enforces, allowing static analysis without running WASM?

### 2. The Project Graph
How does `tinui agent` track dependencies across multiple `.tin` files?
- Do we need an explicit module resolution system?
- How is the AST cached and incrementally updated for cross-file references (e.g. `import Card from components`)?

### 3. LSP Feature Set Design
For rename, definition, and references:
- How does the dispatcher map a 1D text position to a cross-file symbol in the AST?
- What JSON-RPC payloads are required over the machine protocol?

### 4. AI Tooling Surface
How does an autonomous agent interact with the `tinui` protocol?
- Does the agent send complex queries (e.g., `query { component: "Card", dependencies: true }`)?
- How do we expose repair diagnostics (`repair_suggestion`) safely?

## Next Steps

1. **Audit current AST capabilities**: Review `parser.go` and `generator.go` to see how much semantic data is currently preserved vs discarded.
2. **Draft the Semantic Schema**: Propose a JSON Schema for the new typed IR.
3. **Map the LSP extensions**: Define the new JSON-RPC capabilities needed for Advanced LSP.
