# TinPyUI v1.8 — Version Authority & Namespace Audit

This document establishes the authority map for version declarations across the TinPyUI ecosystem, clarifying what each version string actually represents. This ensures we do not blindly unify version numbers across decoupled domains (e.g., product version vs. LSP protocol version).

## Version Authority Map

| Component Declaration | Meaning / Scope | Canonical? | Should be 1.8.0? |
|---|---|:---:|:---:|
| **Go Compiler** (`generator.go`) | The core TinPyUI product & compiler baseline. | ✅ | **Yes** (Current: 1.8.0) |
| **Rust Runtime** (`Cargo.toml`, `lib.rs`) | The core WebAssembly engine execution baseline. | ✅ | **Yes** (Current: 1.8.0) |
| **Project Req** (`tinpyui.project`) | The required compiler/runtime baseline for user apps. | ✅ | **Yes** (Current: >=1.8.0) |
| **CLI Host** (`__main__.py`, `cli.py`) | The unified developer toolchain and UI window. | ✅ | **Yes** (Current: 1.8.0) |
| **Python Package** (`__version__`) | The PyPI distribution version of the Python framework. | ⚠️ | **Audit** (Current: 1.7.2, Docstring: 1.8.0) |
| **Agent / LSP Protocol** (`TinuiVersion`) | The JSON-RPC Machine Protocol and daemon capabilities. | ❌ | **No** (Current: 1.9.0) |
| **VS Code Extension** (`package.json`) | The VS Code Marketplace distribution version. | ❌ | **No** (Current: 1.0.0) |
| **Syntax Extension** (`package.json`) | The VS Code Marketplace distribution version. | ❌ | **No** (Current: 0.0.1) |

## Analysis of Discrepancies

### 1. Python Package (`__version__` in `__init__.py`)
- **Current State**: `__version__ = "1.7.2"`, but the docstring explicitly states `TinPyUI v1.8.0`.
- **Classification**: Stale Metadata.
- **Recommendation**: This is a genuinely stale artifact. The Python package version (for PyPI distribution) should align with the core product baseline. It should be updated to `1.8.0`.

### 2. Agent / LSP Protocol (`TinuiVersion` in `handlers.go`)
- **Current State**: `TinuiVersion: "1.9.0"`.
- **Classification**: Protocol / Agent Identity.
- **Recommendation**: Leave as `1.9.0` (or manage independently). The `agent` package handles the Machine Protocol and LSP extensions, which we actively developed under the Phase 4 ("v1.9") working label. The protocol version does *not* strictly have to match the core execution runtime version.

### 3. VS Code / Syntax Extensions (`package.json`)
- **Current State**: `1.0.0` and `0.0.1`.
- **Classification**: Extension Identity.
- **Recommendation**: Leave as is. IDE extensions are typically versioned entirely independently from the core compiler they interact with. Bumping them to 1.8.0 would create an artificial history on the VS Code Marketplace.

## Conclusion

The product baseline is decisively **1.8.0**.

The only actual correction required to achieve consistency is bumping the Python `__version__` to `1.8.0`, resolving its conflict with its own docstring and the rest of the CLI. The agent's `1.9.0` protocol declaration and the IDE extension versions are correctly decoupled namespaces and should be left alone.
