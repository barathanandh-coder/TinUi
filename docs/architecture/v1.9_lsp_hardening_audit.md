# TinPyUI v1.9 Phase 4.1 — LSP Hardening Audit

This document is the result of a read-only architectural audit of the Phase 3 LSP integration, evaluated specifically for robustness, error recovery, performance, and security under adverse real-world IDE conditions.

## 1. Concurrent Requests
**Status: DEFICIENCY (IMPLEMENTATION ISSUE)**
- **Observation:** The `tinui agent` reads from `stdin` using a single-threaded `bufio.Scanner` loop in `dispatcher.go` (`for scanner.Scan() { ... handleRequest(req) }`).
- **Impact:** Requests are processed purely sequentially. A slow `build` or `check` request will completely block fast semantic queries like `hover` or `completion`. 
- **Ordering guarantees:** Perfect, but at the cost of unacceptable concurrency blocking.
- **Correlation:** JSON-RPC `id` is respected and mapped correctly.

## 2. Cancellation
**Status: DEFICIENCY (PROTOCOL & IMPLEMENTATION ISSUE)**
- **Observation:** The TinPyUI Machine Protocol lacks a formal cancellation schema (e.g., `$/cancelRequest`). The Go agent's handlers are entirely synchronous and do not accept `context.Context` cancellation tokens.
- **Impact:** If a user types 10 characters rapidly, 10 `check` operations queue up. The IDE cannot cancel the first 9, meaning the CPU is thrashed performing expensive, obsolete AST parsing.

## 3. Rapid Document Changes (Debouncing & Stale State)
**Status: DEFICIENCY (IMPLEMENTATION ISSUE)**
- **Observation:** While `test_vfs_agent.py` proves the *protocol* correctly rejects explicitly outdated version queries, the TS middleware blindly forwards every `onDidChangeContent` event to `check` without debouncing. 
- **Impact:** Because the Go agent is single-threaded and lacks cancellation, rapid typing creates a massive backlog of `check` tasks. The middleware receives these in order and eventually publishes the latest diagnostics, but wastes significant system resources doing so. The middleware does not attempt to drop old check promises.

## 4. Crash Recovery
**Status: DEFICIENCY (IMPLEMENTATION ISSUE)**
- **Observation:** `middleware.ts` sets up `agentProcess.stderr.on` and `agentProcess.stdout.on`, but there is no `agentProcess.on('exit')` that attempts a restart.
- **Impact:** If the Go compiler crashes (e.g., due to a panic on malformed AST), the LSP goes permanently dead for the remainder of the VS Code session. There is no auto-restart logic, nor logic to replay the `vfs` (open documents) to a newly restarted agent.

## 5. Large Projects & Memory
**Status: DEFICIENCY (IMPLEMENTATION ISSUE)**
- **Observation:** `handlers.go` reads entire source files into memory as string concatenations. The `vfs` map holds complete copies of every open document indefinitely until `close_document`.
- **Impact:** Opening many large `.tin` files will linearly consume memory. Parsing is done on full string copies rather than memory-mapped or streamed readers.

## 6. Performance
**Status: TECHNICAL DEBT**
- **Startup:** Near-instant (Go binary).
- **Latency:** Because all requests queue behind each other, diagnostics/completion/hover latency is theoretically unbound and directly tied to the queue depth of prior `check` operations. 

## 7. VS Code UX
**Status: TECHNICAL DEBT**
- **Diagnostics:** Properly mapped to native VS Code types (including 0-based indexing corrections).
- **Hover/Completion:** Hardcoded stubs in `handlers.go` return static responses regardless of context.
- **Code Actions:** Successfully implemented, translating deterministic `repair_suggestion` payloads into native Quick Fixes, but execution will feel sluggish due to head-of-line blocking.

## 8. Malformed Protocol Traffic
**Status: PASS**
- **Observation:** `dispatcher.go` strictly enforces `req.JSONRPC == "2.0"` and safely unmarshals params. Unknown methods hit the `default` switch case and return a formal `-32601 Method not found`. Missing parameters return `-32602`. 
- **Impact:** The protocol parser is highly defensive against invalid payloads.

## 9. Resource Lifecycle
**Status: PASS**
- **Observation:** `close_document` correctly purges memory from `vfs`. The middleware properly hooks `connection.onShutdown` and `connection.onExit` to gracefully terminate the Go agent via `sendAgentRequest('shutdown')`.

## 10. Security Boundaries
**Status: DEFICIENCY (IMPLEMENTATION ISSUE)**
- **Observation:** `params.URI` and `params.Entry` in `handlers.go` are trusted blindly. `os.ReadFile(uri)` allows arbitrary file reads anywhere on the filesystem if a malicious client sends a payload like `{"method": "check", "params": {"uri": "../../../etc/passwd"}}`. `build` allows arbitrary directory creation via `outDir`.
- **Impact:** No workspace sandboxing or URI normalization exists.

---

### Audit Conclusion
The Machine Protocol itself is largely structurally sound (PASSing malformed traffic, lifecycle, and versioning gates). However, the protocol lacks a **cancellation primitive**, and the implementations (both Go and TS) suffer from **severe synchronous head-of-line blocking** and **lack crash resilience**. 

To survive real-world IDE usage, the implementation must transition to asynchronous/concurrent request handling, debounce rapid changes, implement restart/replay loops, and sandbox file paths.
