# TinPyUI v1.11 — Phase A.4.6.5: Targeted Regression Audit

This document formally verifies the stability and correctness of the Component Type System before its exposure to the public LSP/Machine Protocol layer.

### 1. Local Components Behavior
- **Result: PASS.** The Type Checker natively falls back to `buildSymbolID(ast.URI, name)` when an invocation isn't present in the local `importMap`. Local intra-file component resolution behaves identically and generates exact diagnostics as proven by the unit tests.

### 2. Legacy Untyped Imported Components
- **Result: PASS.** When an external component like `component Legacy(text, disabled)` is parsed, its `PropDecl` contains empty `TypeHint`s. The type checker translates this to `TypeAny`, effectively turning off strict typing for that property and cleanly accepting any dynamic `kwargs`.

### 3. Typed Imported Components Diagnostic Verification
- **Result: PASS.**
  - **Missing Property**: Triggers if a strictly typed property with no default is omitted.
  - **Unknown Property**: Triggers if an arbitrary keyword arg is provided that does not exist in `Props`.
  - **Duplicate Property**: Triggers if a property is passed via both positional args and named attributes.
  - **Type Conflict**: Triggers if literal inference mismatches the `TypeHint` (e.g. `disabled=42` against `Bool`).

### 4. Import Target Updates
- **Result: PASS.** `CheckWorkspace` is stateless. If a target file is updated on disk, the IDE executes `Workspace.AddFileAST(newAst)`, replacing the `Symbol`. The next `CheckWorkspace` call immediately accesses the new `Symbol.Props` through `ResolveSymbol()`.

### 5. Unresolved → Resolved Transition
- **Result: PASS.** The checker operates on real-time queries. If an imported dependency is initially missing (`IsUnresolved = true`), compiling the missing file inserts its `Symbol`. The next check cycle automatically succeeds.

### 6. Resolved → Unresolved Transition
- **Result: PASS.** If an imported file is deleted, `Workspace.RemoveFile(uri)` wipes its symbols from the index. The Type Checker immediately falls back to `UnresolvedComponentReference`.

### 7. Circular Imports / Rendering
- **Result: PASS.** The `visiting map[string]bool` explicitly tracks recursive resolutions. Re-entering an already active target ID safely terminates the evaluation, returning `Unknown` and suppressing diagnostics. No stack overflows occur.

### 8. Duplicate Component Names
- **Result: PASS.** Because the semantic layer strictly maps symbols via `tinpy://` (e.g. `tinpy://file1.tin#Button` vs `tinpy://file2.tin#Button`), identically named components across different files NEVER mathematically collide.

### 9. Source Range Accuracy
- **Result: PASS.** Every `ComponentDiagnostic` utilizes the precise `Range` of the `ASTNode` (`n.Range`), ensuring squiggly lines in the LSP trace back perfectly to the user's invocation code, avoiding misleading pointers into compiler internals.

### 10. Execution/IR Preservation
- **Result: PASS.** The v1.8 execution baseline was unmodified. The `generator.go` natively leverages the `PropDecl.Name` exactly as it did `Args []string`. AOT WASM and Mobile pipelines remain completely unaffected.

### Essential Diagnostic Rule (Enforced)
When a component resolves to `nil` or `IsUnresolved == true`:
- The Type Checker intentionally **short-circuits**, appending exactly 1 `UnresolvedComponentReference` diagnostic.
- It actively **halts** further evaluation, completely suppressing `MissingProperty`, `UnknownProperty`, and `TypeConflict` errors, ensuring users only see actionable errors (e.g., "Fix your import path first").

---
**Status:** Audit Complete. Architecture is stable and certified for A.4.6.6 LSP exposure.
